# Software Engineering Advising System (Documentation-First, Agile Practice)

This project is a **documentation-focused Software Engineering team project** built to practice a realistic **Agile workflow** while producing the core engineering artifacts you’d create for a real system.

Instead of jumping straight into coding, the goal was to simulate how a real team builds shared clarity first: **what the system should do, how it should be designed, and how it would be tested**. We worked iteratively, reviewed each other’s sections, and kept everything aligned so the requirements, architecture, and test plan told one consistent story.

## What the system is
An **Advising System** designed to support a typical university advising flow, such as:
- organizing advising-related information in one place
- supporting common actions (ex: managing student/advisor interactions, tracking advising needs, and related workflows)
- defining clear system behavior and constraints before implementation

## What this project demonstrates
- **Agile process practice:** iterative planning, frequent check-ins, and incrementally improving deliverables
- **Requirements clarity:** separating functional vs. non-functional requirements and keeping scope realistic
- **Architecture alignment:** defining components and responsibilities so the design matches the requirements
- **Testing mindset:** building a test plan with meaningful test cases tied to the requirements (traceability-focused)

## Key deliverables
- Requirements documentation (functional + non-functional)
- System design / architecture (high-level structure, components, and interaction)
- Test plan and test cases (validating requirements and edge cases)
- Iteration notes and team alignment decisions (scope control + consistency)
